# Minimi Chat design

**Start with the conversation.** A question like “Did any of the five CRM tools we shortlisted Monday change their pricing?” has two evidence sources. The chat tells us which five tools the user means and what the agent said then. The web tells us what can be verified now. Mixing those steps makes it easy to research a plausible substitute shortlist or mistake an old mistake for a price change.

**Retrieve before reasoning.** SQLite keeps timestamped question–answer pairs and citation annotations. For each new message, the server combines recent turns from the active chat, date matches across the browser’s chats, and SQLite FTS5 matches weighted toward user questions. Dates use the browser’s time zone. “Last Tuesday” means Tuesday of the previous Monday–Sunday week. A yearless date means its most recent occurrence. The model receives the resolved dates, match counts, and bounded excerpts of original turns. It can quote the old question, identify ambiguity, or ask for the missing detail. Relative date conventions and lexical recall can miss a user’s intended reference. Both are testable independently of the model.

**One streamed model call.** The Responses API gets the retrieved context and one tool, hosted web search. The model can answer a greeting immediately or refine searches when evidence is thin. For change questions it gets explicit instructions to cover the original entities, seek official pricing pages and dated releases, compare like-for-like tiers and billing periods, and separate a confirmed change from a corrected prior answer or an unknown baseline. Search progress and text stream to the browser, and provider citation annotations become clickable links in the final answer. A completed reply and its citations commit together. Failed or interrupted replies can be retried with the same message ID.

**Tradeoffs.** A separate model call to rewrite or route every question adds latency to greetings and still has to resolve dates correctly. App-side retrieval gives deterministic date lookup with no network hop. I chose FTS5 over embeddings because dates and product names are strong signals in the challenge and SQLite gives us one local dependency. Semantic paraphrases remain a weakness. Hosted search cuts integration work and returns citation metadata. It gives the app less control over parallel source checks and leaves citation relevance to the model and reviewer. Request logs capture first text, first search, tool count, and token usage without recording transcript text.

**Another week.** Build dated fixtures with known pricing and release changes and manually label evidence at the claim level. Measure correct entity recovery, verified changes, unsupported claims, and p50/p95 latency. Use failures to decide whether to add semantic recall for paraphrases or a targeted second pass for comparisons with missing evidence. Keep either change only if it improves the measured cases.
